# AGENTS.md — правила для Codex

Ты работаешь в проекте пиксельной 2D-игры на Godot 4 (GDScript) как **исполнитель**.
Ведущий разработчик — Claude (Claude Code). Задачи тебе ставит он или пользователь.
Делай ровно то, что в задаче, и не расширяй её.

## Что ты делаешь
1. **Графика** через `$imagegen` (gpt-image-2). Главная твоя задача.
2. Типовой код по образцу, на который указывает задача (скопируй структуру образца, не придумывай свою).
3. Данные: списки предметов, диалоги, локализация (`data/`).
4. Тесты и ревью кода (read-only, если не сказано иное).

## Что ты НЕ делаешь
- Не меняешь архитектуру, автозагрузки (`project.godot` → `[autoload]`), структуру папок, настройки проекта.
- Не трогаешь `docs/DECISIONS.md`, `docs/STATUS.md`, `CLAUDE.md`, этот файл.
- Не кладёшь картинки сразу в `assets/`: только в `art/drafts/` (см. ниже).
- Не удаляешь файлы.

## Правила генерации графики
Перед любой генерацией прочитай `docs/STYLE_GUIDE.md` и ТЗ, указанное в задаче (`art/briefs/*.md`).

- **Всегда** передавай референс стиля: `art/style_ref.png` (и дополнительные референсы из ТЗ, если есть — обычно из `art/refs/<scene>/`; `_sheet.jpg` не передавай, это служебный лист).
- **Фон:** сплошной чистый `#FF00FF` (маджента) без градиентов, теней на фоне и виньетки. Прозрачность не используй: фон вырежет скрипт.
- **Стиль:** пиксель-арт, чёткие крупные «пиксели» одинакового размера, без сглаживания, без размытия, без шума и мелкой текстуры, ограниченная палитра (`art/palette.png`), тёмный контур, как в STYLE_GUIDE.
- **Композиция:** один объект по центру с полями ≥10% (если ТЗ не требует лист). Для спрайт-листов — строго ровная сетка из N одинаковых ячеек в одну строку, объект в каждой ячейке на одном и том же месте, одинаковый масштаб.
- **Тайлы:** вид строго сверху или сбоку, как в STYLE_GUIDE; края должны стыковаться (seamless), если это указано в ТЗ.
- Не добавляй текст, подписи, водяные знаки, рамки.
- Сохраняй в `art/drafts/<id_из_ТЗ>/v<N>_<вариант>.png` (например `art/drafts/hero_idle/v1_a.png`). По умолчанию 3 варианта, если ТЗ не говорит иное.
- После генерации запиши в `art/drafts/<id>/README.md`: дату, итоговый промпт, использованные референсы.

## Формат отчёта (коротко)
```
Сделано: <что>
Файлы: <пути>
Проблемы/сомнения: <если есть>
```

## Код
- Godot 4.x, GDScript со статической типизацией, имена файлов `snake_case`, классы `PascalCase`.
- Не ломай формат `.tscn`/`.tres` (`[ext_resource]`, `uid://`, `id`).
- Проверка: `godot --headless --path . --check-only -s res://<путь>.gd`.

## Новые ракурсы локации
Если в задаче есть `art/refs/<location>/plan/` (floor_plan.png, walls.png, plan.md) — это ЗАКОН для расстановки: стены, окна, мебель и предметы ставить строго по плану и развёртке; камера — где отмечена. Стиль-референсы не дают права переставлять предметы.
