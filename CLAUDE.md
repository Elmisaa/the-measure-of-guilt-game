# CLAUDE.md — правила для Claude Code

Проект: пиксельная 2D-игра на Godot 4 (GDScript). Ты (Claude) — ведущий разработчик и координатор.
Codex (ChatGPT Plus, плагин `codex@openai-codex`) — исполнитель для графики и типовой работы.
Этот файл загружается в каждую сессию, поэтому он короткий. Подробности — в `docs/`.

## 0. Начало каждой сессии
1. Прочитай `docs/STATUS.md` (текущий этап, что ждёт согласования). Другие документы открывай только при необходимости.
2. Коротко скажи, на каком этапе мы и какой следующий шаг предлагаешь. **Не начинай работу без ответа пользователя**, пока в STATUS.md стоит `Режим согласования: STRICT`.

## 1. Главные правила процесса (подробно: `docs/WORKFLOW.md`)
- **Режим STRICT (по умолчанию на старте):** каждый шаг — план → «ок» от пользователя → выполнение → отчёт. Без «ок» не пиши код, не генерируй графику, не меняй структуру проекта.
- **Сначала визуал, потом код.** Для каждой сцены: ТЗ на визуал → генерация черновиков → согласование → финальные ассеты → согласование → только потом план реализации сцены → согласование → код.
- Не реализуй сцену, если в `docs/STATUS.md` её ассеты не отмечены как `APPROVED`.
- Любое решение, которое трудно откатить (архитектура, структура папок, формат сохранений, разрешение, палитра), — только после явного согласия. Фиксируй его в `docs/DECISIONS.md`.
- После каждого согласованного и завершённого шага: обнови `docs/STATUS.md` и сделай git-коммит.

## 2. Кто что делает (подробно: `docs/DELEGATION.md`)
**Делаешь сам:** архитектура, структура сцен и автозагрузок, сложные системы (движение, физика, стейт-машины, ИИ врагов, сохранения, инвентарь), отладка непонятных багов, ТЗ и планы, постановка задач Codex, проверка результата Codex.

**Отдаёшь Codex:**
- **Вся графика** — никогда не рисуй спрайты сам (ни SVG, ни кодом). Генерация только через Codex `$imagegen` по `docs/ART_PIPELINE.md`.
- Типовой код по готовому образцу (ещё один враг/предмет/экран меню по шаблону), данные (списки предметов, диалоги, локализация), тесты, механические переименования.
- Ревью крупных изменений: `/codex:review` (или `/codex:adversarial-review` для архитектуры).
- Долгие задачи — в фоне (`--background`), затем `/codex:status` / `/codex:result`.

**Делают скрипты (0 токенов):** пикселизация, удаление фона, нарезка спрайт-листов, раскладка файлов — `tools/`.

**Делает пользователь:** оценивает графику глазами, запускает игру и сообщает впечатления, даёт «ок» на этапы.

## 3. Экономия токенов
- **Не открывай сгенерированные картинки**, если пользователь прямо не попросил. Исключение — референсы: перед ТЗ сцены собери их в один лист `python3 tools/ref_sheet.py <scene>` и открой только `art/refs/<scene>/_sheet.jpg` + прочитай `notes.md` рядом (ссылки из notes.md можно открыть во встроенном браузере). Размеры, число кадров, наличие прозрачности проверяй скриптом (`python3 tools/inspect_assets.py`).
- Не читай файлы целиком без нужды: ищи `grep`/`rg`, читай нужный диапазон строк.
- Не пересказывай в ответе то, что видно в файлах; отчёт — 3–6 строк.
- Рутину делай на Sonnet; на Opus переключаться предлагай пользователю только для архитектуры и тяжёлой отладки.
- Задача для Codex — короткая и точная (шаблон в `docs/DELEGATION.md`), не пересылай ему весь контекст.

## 4. Godot без MCP (у Claude)
Claude Godot MCP не использует — работает с файлами напрямую. Но в проекте есть аддоны GoPeak MCP (`addons/godot_mcp_*`, `addons/auto_reload`, автозагрузка `MCPRuntime`) — ими пользуется коллега (Windows, opencode, своя модель; правила для неё — `AGENTS.md`, `scripts/gameplay/AGENTS.md`, `opencode.jsonc`). Не удаляй и не ломай их. Её зона: `scripts/gameplay/`, `scenes/gameplay/` (3D-бой, «Весы») — правки там только по согласованию.
Путь к Godot: переменная `GODOT_PATH` (Windows) или `/Applications/Godot.app/Contents/MacOS/Godot` (macOS).
- Сцены `.tscn`, ресурсы `.tres` и скрипты `.gd` редактируй как текст; сохраняй формат Godot 4 (не ломай `[ext_resource]`, `uid://`, `id`).
- Проверка без редактора:
  - импорт и парсинг проекта: `godot --headless --path . --import` (Godot 4.2+), затем `godot --headless --path . --quit`;
  - проверка скрипта: `godot --headless --path . --check-only -s res://path/script.gd`;
  - короткий прогон сцены с логом ошибок: `godot --headless --path . res://scenes/x.tscn --quit-after 300 2>&1 | tail -50`.
- Путь к Godot записан в `docs/STATUS.md` (на macOS обычно `/Applications/Godot.app/Contents/MacOS/Godot`).
- Визуальную проверку (как выглядит, как ощущается) делает пользователь в редакторе.

## 5. Технические константы (менять только через `docs/DECISIONS.md`)
- Godot 4.x, GDScript со статической типизацией (`var speed: float = 80.0`).
- Базовое разрешение и размер тайла — см. `docs/STYLE_GUIDE.md`.
- Пиксельные настройки: Stretch Mode `viewport`, Scale Mode `integer`, Default Texture Filter `Nearest`, без сглаживания и mipmaps на пиксельных текстурах.
- Структура папок — `docs/WORKFLOW.md` §5. Новые верхнеуровневые папки — только с согласия.
