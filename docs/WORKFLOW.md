# Процесс разработки

## 1. Режимы согласования
Режим записан в `docs/STATUS.md`. Переключает **только пользователь**.

| Режим | Что согласуется | Когда |
|---|---|---|
| **STRICT** (старт) | Каждый шаг: план → «ок» → выполнение → отчёт → «ок» | Пока не устоялись стиль, архитектура и привычный ритм |
| **NORMAL** | Этапы (ворота ниже) и любые необратимые решения; мелкие шаги внутри одобренного плана без отдельного «ок» | Когда пользователь скажет «переходим в NORMAL» |

В любом режиме **без согласия нельзя**: менять архитектуру/структуру папок/настройки проекта, тратить много лимита Codex (больше 10 генераций за раз), удалять файлы, менять уже `APPROVED` ассеты.

Формат запроса на согласование (коротко):
```
Шаг: <что предлагаю>
Зачем: <1 строка>
Что изменится: <файлы/ассеты>
Кто делает: Claude / Codex / скрипт
Жду: ок / правки
```

## 2. Этапы проекта (ворота согласования)
```
Э0 Настройка среды        → G0: среда работает (docs/SETUP.md)
Э1 Концепция (GDD-lite)   → G1: пользователь одобрил docs/GDD.md
Э2 Стиль                  → G2: одобрены STYLE_GUIDE, palette.png, style_ref.png
Э3 Сцена N: визуал        → G3: одобрены ассеты сцены (см. §3)
Э4 Сцена N: реализация    → G4: пользователь поиграл и принял сцену
   (Э3–Э4 повторяются для каждой сцены)
Э5 Полировка и сборка     → G5: релизная сборка
```

## 3. Цикл одной сцены (главный порядок работы)
Визуал всегда идёт раньше кода.

0. **Референсы и идеи.** Пользователь кладёт картинки в `art/refs/<scene>/` и (по желанию) пишет `notes.md`: что нравится в каждой, ссылки. Claude собирает лист `tools/ref_sheet.py <scene>`, смотрит его и предлагает идеи. См. `art/refs/README.md`.
0а. **План локации (обязательно для каждой новой локации).** Claude рисует схемы `art/refs/<location>/plan/`: `floor_plan.png` — вид сверху (стены, окна, двери, мебель, где сидит/стоит герой, откуда смотрят уже утверждённые камеры) и `walls.png` — развёртка всех стен (что на каждой стене слева направо). Текстом — `plan.md` (таблица предметов и их мест). Генерируются из уже утверждённых кадров; утверждает пользователь. **Каждое ТЗ на новый ракурс этой локации ссылается на план**: камера отмечается на `floor_plan`, Codex получает план + развёртку + вырезки из утверждённых кадров, а не «стиль-референсы». Так предметы и интерьер остаются на местах.
1. **ТЗ на визуал.** Claude пишет `art/briefs/<scene>.md` по шаблону `docs/templates/ART_BRIEF.md`: список всех ассетов сцены (фон, тайлы, персонажи, анимации, объекты, UI), размеры, кадры, референсы. → **согласование ТЗ**.
2. **Черновики.** Claude ставит задачу Codex (`$imagegen`), Codex кладёт варианты в `art/drafts/`. Claude не открывает картинки, только проверяет скриптом, что файлы есть.
3. **Выбор.** Пользователь смотрит черновики (в Finder/Preview) и пишет: «hero_idle — v1_b, tileset — переделать: темнее». → итерации, пока всё не выбрано.
4. **Финализация.** Скрипт `tools/pixelize.py` из выбранных вариантов делает финальные ассеты: вырезает фон, приводит к размеру сетки и палитре, режет спрайт-листы → `assets/`. Скрипт `tools/make_preview.py` собирает превью-лист `art/previews/<scene>.png` в увеличении ×4.
5. **Согласование визуала.** Пользователь смотрит превью-лист (а при желании — ассеты в Godot). → в `docs/STATUS.md` сцена получает `Визуал: APPROVED`.
6. **План реализации.** Claude пишет `docs/scenes/<scene>.md` по шаблону `docs/templates/SCENE_SPEC.md`: узлы, скрипты, сигналы, что делает Claude, что Codex. → **согласование плана**.
7. **Реализация.** Claude — каркас и сложная логика; Codex — типовые части по образцу. Проверка через headless Godot (см. CLAUDE.md §4).
8. **Ревью.** `/codex:review` по изменениям сцены; Claude исправляет найденное.
9. **Приёмка.** Пользователь запускает сцену и даёт фидбек → правки → `Сцена: ACCEPTED`, коммит.

Нельзя переходить к шагу 7, пока у сцены нет `Визуал: APPROVED` и согласованного плана.

## 4. Git
- Коммит после каждого принятого шага: `[Э3][forest] approve visual`, `[Э4][forest] player movement`.
- Перед крупными изменениями отдельная ветка `scene/<name>`, слияние после G4.
- `art/drafts/` в git не коммитится (`.gitignore`), только `art/briefs/`, `art/previews/`, `assets/`.
