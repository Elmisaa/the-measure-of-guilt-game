# Руководство по работе с проектом

Основные требования собраны в [корневом AGENTS.md](../AGENTS.md). Для игровых правил и постановки отдельных глав используй [GDD](GDD.md) и спецификации в [`docs/scenes/`](scenes/).

## Код и сцены

- `scenes/` содержит сцены и ресурсы Godot, `scripts/` — их логику, `data/` — диалоги и данные предметов. Общие системы и автозагрузки находятся в `scripts/autoload/`.
- Сохраняй существующие входы в сцены и поведение, на которое опираются другие главы. При изменении переходов, инвентаря или сохранений проверяй затронутые сюжетные маршруты.
- При редактировании `.tscn` и `.tres` сохраняй формат Godot, пути и идентификаторы ресурсов. При переносе ресурса проверь все ссылки на него.
- Базовый кадр игры — 640×360. Для пиксельных текстур используй существующие настройки фильтрации, а размеры интерфейса проверяй в игровом окне.

## Проверка в Godot

Из корня проекта выполни импорт для новой копии, затем запусти существующие тесты затронутой механики или главы. Например, для сохранений и финала:

```bash
godot --headless --path . --import
godot --headless --path . -s res://tests/test_saves.gd
godot --headless --path . -s res://tests/test_finale.gd
```

Вместо `godot` можно использовать полный путь к бинарнику или `"$GODOT_PATH"`. Для проверки изображения и ввода запусти нужную сцену с окном Godot. Тестовые скрипты из `res://tests/` используют отдельную папку сохранений. GoPeak можно использовать для диагностики, если он подключён.

## Графика

1. Перед генерацией прочитай [STYLE_GUIDE.md](STYLE_GUIDE.md) и ТЗ сцены из `art/briefs/`, если оно есть. Используй `art/style_ref.png` как эталон и добавь референсы сцены, указанные в ТЗ.
2. При новом ракурсе сверяй стены, окна, предметы и положение камеры с планом в `art/refs/<location>/plan/`, если он есть.
3. Сохраняй чёткую пиксельную сетку. Для спрайт-листа держи одинаковые размер ячейки, масштаб и положение объекта. Используй `#FF00FF` для вырезаемого фона, если дальнейшая обработка рассчитана на него. Для непрозрачных фонов и правок готовых кадров соблюдай формат исходного ассета или ТЗ.
4. Сохраняй черновики как `art/drafts/<id>/v<N>_<вариант>.png`. Для сгенерированных вариантов запиши в README этой папки дату, промпт и референсы. Подключай одобренный вариант или предоставленный пользователем готовый арт из `assets/`.
