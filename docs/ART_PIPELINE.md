# Пайплайн графики

```
ТЗ (art/briefs) ─► Codex $imagegen ─► art/drafts ─► выбор пользователем
   ─► tools/pixelize.py ─► assets/ ─► tools/make_preview.py ─► art/previews ─► APPROVED
```

## Почему так
gpt-image-2 рисует картинку, похожую на пиксель-арт, но не настоящий спрайт по сетке: пиксели разного размера, полутона, нет прозрачности. Поэтому:
- генерация всегда на фоне `#FF00FF` → скрипт вырезает фон;
- генерация в высоком разрешении → скрипт уменьшает до целевого размера (nearest) и привязывает к палитре `art/palette.png`;
- стиль держится за счёт одного эталона `art/style_ref.png`, который передаётся в каждую генерацию.

## Скрипты (tools/)
| Скрипт | Что делает |
|---|---|
| `pixelize.py <in.png> --size 32x32 [--frames 4] --out assets/...` | Вырезает маджента-фон → обрезает по объекту → уменьшает до размера (nearest) → квантует в палитру → для листов режет на кадры и собирает ровную сетку |
| `make_preview.py <scene>` | Собирает все ассеты сцены из ТЗ в один лист ×4 с подписями → `art/previews/<scene>.png` |
| `inspect_assets.py [путь]` | Печатает размеры, число кадров, есть ли альфа, цвета вне палитры (для Claude, вместо просмотра картинок) |

Скрипты пишет Claude один раз на этапе Э0/Э2 (Python 3 + Pillow).

## Импорт в Godot
- Текстуры: фильтр Nearest (глобально в Project Settings), без mipmaps.
- Спрайт-листы → `SpriteFrames` для `AnimatedSprite2D` (Claude собирает `.tres` текстом по hframes).
- Тайлсеты → `TileSet` с размером тайла из STYLE_GUIDE.

## Статусы ассета (в ТЗ и STATUS.md)
`TODO` → `DRAFTS` → `PICKED (v1_b)` → `FINAL` → `APPROVED`
`APPROVED`-ассеты не меняются без согласия пользователя.

## Если результат плохой
1. Сначала меняем промпт и/или добавляем референс (1–2 итерации).
2. Если генерация не держит сетку (анимации, 8 направлений), предлагаем пользователю: отдельные кадры по одному, ручная доводка в Aseprite или отдельный сервис для пиксель-арта (например PixelLab). Решает пользователь.
